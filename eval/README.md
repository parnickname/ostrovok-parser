# Диалоги для проверки памяти (P2-DS-03.1)

Пять пар сессий для eval фазы 3 (CFC-11, спека 0005 основного проекта). В каждой паре первая сессия называет одно
устойчивое предпочтение вместе с разовой поездкой, вторая сессия того же владельца его не повторяет, и агент должен
подставить значение из профиля.

Прогонщик eval живёт в репозитории бэкенда: файлы отсюда копируются туда как есть.

## Файлы

`eval/cases/memory-NN-<ключ>.json`, по одному на пару, `split: dev`. Ключи профиля (CFC-7) у пар разные:

| Файл | Ключ профиля | Что называет первая сессия | Что должна выдать вторая |
|---|---|---|---|
| `memory-01-origin.json` | `origin` | живёт в Казани | допущение `origin: kazan` из профиля, вопроса «откуда вылетаете» нет |
| `memory-02-pets.json` | `pets` | едет с собакой | допущение `pets: true`, отели с `pets: false` не предлагаются |
| `memory-03-family.json` | `adults`, `child_ages` | двое взрослых, дети 4 и 9 лет | допущения `adults: 2`, `child_ages: [4, 9]` |
| `memory-04-free-cancellation.json` | `free_cancellation` | бронировать только с бесплатной отменой | допущение `free_cancellation: true`, невозвратные тарифы не показываются |
| `memory-05-transport.json` | `transport_modes` | только поезд | допущение `transport_modes: ["train"]`, план на поезде |

Направление и даты первой сессии (`destination`, `dates`) в профиль не попадают: в каждой паре они перечислены в
`must_not_carry_over`, во второй сессии они другие.

## Формат

Формат CFC-11 в этом репозитории не описан, поэтому это допущение DS; бэкенд пришлёт поправки, когда фаза закончится.

```json
{
  "id": "memory-01-origin",
  "split": "dev",
  "kind": "memory",
  "profile_key": "origin",
  "owner": "eval-memory-01-origin",
  "sessions": [
    {"turns": [{"role": "user", "text": "..."}]},
    {"turns": [{"role": "user", "text": "..."}],
     "expect": {
       "assumptions": [{"key": "origin", "value": "kazan", "source": "profile"}],
       "constraints": {"origin_city_id": "kazan"},
       "must_not_ask": ["origin"],
       "must_not_carry_over": ["destination", "dates"]
     }}
  ],
  "note": "..."
}
```

- `sessions` — две сессии одного `owner`: между ними память профиля сохраняется, диалог нет. Граница сессий задана
  самим массивом, ожидание лежит в `expect` второй сессии.
- `turns` — только реплики пользователя: ответы агента прогонщик получает от самого агента.
- `expect.assumptions` — допущения, которые агент обязан записать с `source: profile` (CFC-7: `origin: profile`);
  значения города — `id` из `cities` снапшота, транспорт — `train`, `air`.
- `expect.constraints` — что должно быть правдой в итоговом плане; `must_not_ask` — какие вопросы агент задавать не
  должен; `must_not_carry_over` — что из первой сессии во второй попасть не должно.
- Тексты ссылаются на данные снапшота: Казань, Москва, Сочи, Санкт-Петербург, Анталья, Будапешт — направления или города
  отправления с аэропортами и вокзалами, а `rail_routes` содержит Москву — Казань и Москву — Сочи.
